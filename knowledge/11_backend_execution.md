# Backend: Execution

## File Paths: `src/research_ai/execution/`
## Status: Active / Specialized

## Description
This directory handles the deterministic execution of code and rigid pipelines.

## File Breakdown

### 1. `src/research_ai/execution/pipelines/service.py`
- **Class `PipelineService`**: Allows for rigid, non-agentic workflows.
- **Functions**:
  - `run_pipeline(name, inputs)`: Bypasses the LLM Planner and forces a hardcoded sequence of tools (e.g., `hybrid_search` -> `cluster_papers` -> `summarize_clusters`). Useful for predictable background tasks.

### 2. `src/research_ai/execution/python_runner/service.py`
- **Class `PythonRunner`**: Provides a way for the AI to write and execute Python code.
- **Functions**:
  - `execute(code)`: Takes a string of Python code generated by the LLM and runs it via `subprocess` or `exec`.
  - **Security**: Heavily sandboxed. Generally disabled in production web environments unless strictly necessary for plotting graphs or calculating statistics on research data.

### 3. `src/research_ai/execution/sandbox/service.py`
- **Class `SandboxEnvironment`**: 
- **Functions**:
  - `create_environment()`: Sets up a temporary, isolated Docker container or constrained execution context for `PythonRunner` to ensure malicious LLM code cannot access the host machine's environment variables or file system.
