# RAG Runtime Trace (Test A As-Is)

This document traces the actual RAG pipeline implementation from the API entrypoint down to the LLM response in the **current, unmodified Research AI application**.

## 1. `/ask` Workflow Trace

1. **Endpoint**: `POST /ask`
   - Receives: `AskRequest` (`query`, `top_k`)
   - Action: Calls `platform.orchestrator.run(mode="auto", query=query, top_k=top_k)`
2. **Orchestrator**: `ResearchOrchestrator.run()`
   - Logs: `[ORCHESTRATOR] Starting request...`
   - Action: Passes the query to `PlannerAgent.plan()`.
3. **Planner**: `PlannerAgent.plan()`
   - Constructs a prompt containing the user's query and the list of available tools.
   - Calls the **Cloud LLM** (e.g., Groq, OpenRouter) to determine the next steps.
   - LLM responds with a JSON array of tool calls. (e.g., `[{"tool": "search_papers", "args": {"query": "..."}}]`)
4. **Executor**: `MLExecutionAgent.execute()`
   - Iterates through the tool calls generated by the Planner.
   - Maps `search_papers` to `platform._hybrid_search()`.
5. **Retrieval**: `platform._hybrid_search()`
   - Calls the **local** `HybridSearchService` (`self.retriever.search()`).
   - The retriever uses the **local** `EmbeddingService` to encode the query (loads into local RAM).
   - The retriever queries the **local** `FaissVectorStore` (inner product search over local RAM).
   - If external APIs (ArXiv, CrossRef) are enabled, they are queried and merged via local BM25 ranking (`AcademicSearchService`).
   - Returns a list of retrieved papers.
6. **Context Assembly (Implicit)**
   - The `MLExecutionAgent` aggregates the JSON responses from all executed tools into an `execution_results` dictionary.
7. **Synthesis**: `SynthesisAgent.synthesize()`
   - Receives the original query and the `execution_results` (the retrieved context).
   - Constructs a massive prompt containing the retrieved paper abstracts.
   - Calls the **Cloud LLM** to generate the final grounded response.
8. **Response**: 
   - Returns the LLM string as the API response.

## 2. `/chat/message` Workflow Trace

1. **Endpoint**: `POST /chat/message`
   - Receives: `ChatMessageRequest` (`message`, `conversation_id`, etc.)
   - Action: Calls `platform.chat()`
2. **State Retrieval**: `ConversationStore`
   - Loads the previous messages for this `conversation_id` from local memory.
3. **Orchestrator**: `ResearchOrchestrator.run(mode="chat")`
   - The planner receives the full conversation history to maintain context.
   - The planner decides if retrieval is needed based on the history.
4. **Retrieval & Synthesis**: Same as `/ask`.
5. **State Update**:
   - The user query and the final response are appended to the `ConversationStore`.

## Summary
The current RAG pipeline relies entirely on the **local** instantiation of ML models (Embedding, FAISS) for the retrieval phase. The LLM components (Planner, Synthesizer) correctly call the external cloud provider, but the Hugging Face remote microservice is bypassed during internal RAG execution.
